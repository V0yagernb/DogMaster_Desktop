# 决策记录（ADR）

本文件记录「把狗头军师与进程聊天工具合成一个桌面程序」这件事上，被明确拍板过的每一个决定。
每条都写清了**结论、理由、代价**，方便以后推翻时有据可查。

---

## ADR-0001 交付形态：exe 主入口 + 技能包辅助入口

**结论**：做一个桌面 exe 当日常主入口，同时保留一个 DSH 技能包（`goutou-chat`）当对话入口，两者共用同一套档案与规则。

**理由**：GUI 适合"盯着回"这种连续操作；但"帮我看看这段/这句话怎么回"在对话里问更快。

**代价**：两处入口都要维护；好处是规则与档案只有一份。

---

## ADR-0002 只有两档：建议档 / 全自动档

**结论**：不设"拟稿后等确认"的中间档。建议档＝只给判断与草稿，由本人自己发；全自动档＝程序直接发。全自动档内部再分三个子档：

- **单次**：点名一次，发完即失效
- **常驻**：点名进入后，持续自动回到本人叫停或触发停手条件
- **限时**：与常驻相同，但到点自动收回授权

**理由**：本人明确要求"就两个档"，不要中间态。

**代价**：拆掉了"每句话都有人点头"的闸门，所以安全必须靠白名单、红线清单、发送前检查点与紧急制动来补（见 ADR-0004、ADR-0013）。

---

## ADR-0003 启动权永远在本机使用者手里

**结论**：后台盯未读**只产草稿，绝不自动发送**。三个子档只决定"本人开聊之后自动回多久"，不改变"必须有本人发起的动作"这一点。

**理由**：若后台能自动发，等于程序可以在本人不知情时替本人说话。

**代价**：不能做"人不在也能自动应答"的产品；这是有意为之。

---

## ADR-0004 白名单制；群聊永不进全自动

**结论**：只有被点名的对象能进全自动；**任何群聊（微信 @chatroom）一律只提醒不代发**。

**理由**：群聊黑话密度高、语境无法验证，发错一句就是公开事故；且身份映射本身存在不确定性，群聊不进全自动等于给映射错误加了一道保险。

**代价**：群聊A、好友群只能当"提醒器"。

---

## ADR-0005 技术栈：Python 3.9 + PyQt5 + PyInstaller

**结论**：用本机已有的 Python 3.9.13 + PyQt5 5.15.11；打包用 PyInstaller（需联网补装）。

**理由**：实测本机唯一齐备的 GUI 栈就是这套；调 PowerShell、读 SQLite、注册全局热键（pywin32 已在）全都顺手。

**代价**：Python 3.9 偏旧；不用最新的 PySide6/PyQt6。

---

## ADR-0006 截图只用于核对面孔，用完即删；聊天文本明文

**结论**：只在切换会话时截一张 header 图用于核对"是不是这个人"，用后立即删除；聊天文本明文存在 `关系档案\`。

**理由**：读消息走本地解密库，本来就不需要截图；截图是最容易外泄的一块，没必要攒。文本明文只留在本机数据根，永不进版本库（ADR-0025）。

**代价**：出问题无法回看历史截图。

---

## ADR-0007 大脑通路：DSH 子进程；不读本机凭据库

**结论**：程序把"分析 + 拟稿"交给本机 DSH，走 `dsh` 的 headless / sdk 子进程（stdio），**不采用**"复用 3080 并自签 cookie"那条路。

**理由**：自签 cookie 需要读 `<DSH 主目录>\.credentials.yaml` 里的签名密钥，等于把主会话钥匙交给一个会自动发消息的程序，这个代价不该付。子进程路线不需要任何凭据，也不碰正在跑的服务。

**代价**：每次分析多几秒进程启动（常驻 sdk 子进程可缓解）；依赖 DSH 安装在那台机器上。

---

## ADR-0008 档案根：`F:\goutoujunshi\关系档案\`，桥接层独占写入

**结论**：画像、记忆库、语料、复盘、配置全部落在项目内的 `关系档案\`；由本项目（程序或技能）**独占写入**。

**理由**：技能包目录会被上游整包升级覆盖，数据不能住在代码目录里；两处各写各的迟早自相矛盾。

**代价**：要让原 `process-chat-tool` 技能继续读到画像，需要在它的 `style\` 位置放一个目录联接（junction）指向新位置。

---

## ADR-0009 军师知识引用不复制

**结论**：技能包与程序都按需读取军师原目录的参考文件（`<你的用户目录>\.agents\skills\goutoujunshi\references\`），不复制进本项目。

**理由**：军师自己的规矩就是"按需加载 1–3 份"；复制会腐烂，且上游一更新就会出现混血版本。

**代价**：依赖那个目录存在（本机该目录是 `.claude\skills\goutoujunshi` 的 Junction 目标）。

---

## ADR-0010 上游零件冻结复制

**结论**：把 `pct.ps1`、`targets\*.json` 复制一份到本项目的 `vendor-frozen\`，程序只调这份副本。

**理由**：exe 是交付物，不能依赖另一个工作区的文件还在不在。冻结副本要注明来源与日期。

**代价**：上游改进不会自动进来，需要人工同步（会在项目文档里写明）。

---

## ADR-0011 读消息走 HTTP 直连，不经过 wc.ps1

**结论**：直接用 HTTP 打读取后端 `http://127.0.0.1:10392` 的只读端点（`/api/chat/sessions`、`/api/chat/messages` 等）；`wc.ps1` 只在排障时用。

**理由**：省掉每次起 PowerShell 的一秒多开销，能常驻、能并发；数据契约已经实测稳定。

**代价**：端口变化时要靠 `desktop-settings.json` / `WECHAT_TOOL_PORT` / `/api/health` 三种方式发现。

---

## ADR-0012 冲突优先级

**结论**：**安全与法律 > 发送红线 > 军师的推进建议 > 一般闲聊策略**。

**理由**：军师负责"说什么"，代聊负责"能不能发、怎么发"；两者冲突时后者一票否决。

**代价**：某些时候会显得"不够会撩"，这是刻意换安全。

---

## ADR-0013 紧急制动：全局热键 + 发送前检查点

**结论**：默认热键 `Ctrl+Alt+Esc`，**仅在全自动态生效**；制动后停止一切后续发送，并丢弃所有"已拟好未发"的内容；每条消息在真正注入键盘之前必须再过一次制动检查。

**理由**：窗口被别的程序压住时界面按钮点不到（本机有 QQMusic / DSH 轮流压住微信的历史），热键是唯一可靠的救命手段；不打断"已经进键盘"的那一条，避免留下半句话。

**代价**：制动的那一瞬间可能已经有一条消息发出去了，这一点必须如实告诉使用者。

---

## ADR-0014 退出时长由使用者自填

**结论**：全自动态在"最后一次有实际动作"后经过**使用者自填的时长**（默认 15 分钟）自动退出，回到建议档；程序继续运行，界面明确显示状态并留日志。

**理由**：本人要求时长自己填；默认给 15 分钟。

**代价**：忘填/填得过长时要靠紧急制动兜底。

---

## ADR-0015 工具时效预案

**结论**：读取后端的原生组件自构建起 45 天失效。到期前 7 天开始提醒；未升级期间自动降级为"截图读图"通道。

**理由**：升级是安装第三方程序，由本人拍板，程序不擅自下载安装。

**代价**：降级期间速度与准确度都会下降。

---

## ADR-0016 语料纳入版本库 + 禁止推送护栏（已被 ADR-0025 修订）

**结论（历史）**：曾把本人私聊语料纳入 git，并安装 `pre-push` 钩子拒绝一切 `git push`。**这一状态已在 1.0.0 交付前撤销，见 ADR-0025。**

**理由**：仓库当前无远端、从未推送，明文可接受；但私聊记录一旦被推出去就收不回来，用几行钩子把这条路锁死。

**代价（历史）**：当时若要备份到远端，必须先手动卸掉钩子（有意的摩擦）。

---

## ADR-0017 身份映射

**结论**：亲友类群会话（群聊A、群聊B）按会话名映射；走 QQ 通道的联系人不占微信白名单；其余个人会话默认只走建议档。

**理由**：前两条是名称对不上号的推测，需在下一次实际使用时核对。

**代价**：映射错了也不会误发——群聊永不进全自动（ADR-0004）。

---

## ADR-0018 事后复盘三样都做

**结论**：一轮自动对话结束后，① 在界面上给一段复盘摘要；② 写一份 `关系档案\复盘\日期-对象.md`；③ 只把**稳定事实**（约好的事、冲突、修复）写进军师记忆库（受 200 条配额约束，日常寒暄不写）。

**理由**：复盘文件给人回看，记忆库给下一轮判断用，两者长度和用途不同。

**代价**：记忆库配额小，必须克制，否则会一直报 `MEMORY_LIMIT_REACHED`。

---

## ADR-0019 大脑改直连，DSH 子进程降为兜底（0.3.0）

**结论**：军师的"分析 + 拟稿"不再默认走 DSH 子进程，改成**直连各家的 OpenAI 兼容接口**（`llm.py`），支持 SSE 流式；DSH 那条路保留为**兜底**（`advisor.py`：直连拿不到结果时自动回退）。

**理由**：实测一次建议 2.6~3.0 秒，其中 **1.87 秒（65~72%）是"起 node 进程 + 装配 profile + 读凭据 + 建会话"**，模型真正往返只有 0.6~0.9 秒；而且 `headless` 不支持流式、也没有常驻模式，`--session-id` 复用会话只省 200~300 毫秒。也就是说：**只要还在起子进程，这条路就快不了**。

**代价**：
- 需要一把 API key，并且聊天记录会离开本机（因此有了 ADR-0020）；
- 直连的 prompt 由本项目自己拼（不再借 DSH 的 agent 配置），军师知识要自己挑；
- 多了一条要维护的通道，以及"回退"这一层状态。

**必须遵守的一条**：回退时**状态栏必须写明"这次走的是兜底通道"**，不许让人以为它变快了。

---

## ADR-0020 群聊不给建议（0.3.0 起，原 ADR-0004 的延伸）

**结论**：群聊（`@chatroom`）不只不进全自动，**连建议也不给**：点开群会话时军师按钮灰掉并写明原因（`rules.advice_allowed()`）。

**理由**：本人明确"狗头军师是用来恋爱的，不是用来处理工作的"，并决定群聊、甲方、工作这三类不进军师。群聊不用人工标记就能自动识别，所以在"每个会话一个开关"（0.4.0）做出来之前，先用这条硬规矩守住边界——同时也就守住了"群聊记录不送去第三方模型"这条隐私线。

**代价**：0.3.0 阶段没有办法给某个群开建议；群聊A、好友群只能自己看消息。

---

## ADR-0021 API key 存项目数据根，不读 DSH 凭据库（0.3.0）

**结论**：直连用的 key 由本人填进设置窗口，存到 `关系档案\配置\secrets.json`（已写进 `.gitignore`）；**程序不去读** `<DSH 主目录>\.credentials.yaml`。

**理由**：延续 ADR-0007 的精神——那是主会话的钥匙库，交给一个会自动发消息的程序不划算；而且本项目自己的 key 就该住在自己的数据根里，备份、迁移、销毁都清清楚楚。

**代价**：换 provider 或换 key 时要手动填一次；这份 key 在本机是明文（永不进版本库，见 ADR-0025）。

---

## ADR-0022 显式指定思考档位 + 两段式出稿（0.3.1）

**结论**：直连请求**必须显式带上 `reasoning_effort`（默认 `low`）**，不能依赖服务端的默认值；
出稿拆成两段：第一段只带"对话 + 说话风格 + 这个人"，只要【判断】【首选】；第二段才带军师知识，
补【备选】【风险】。

**理由**：0.3.0 交付后实测"让军师看一眼"要等 **136 秒**才出第一个字。排查结论是两件事：
1. 智谱 `glm-5.3` 系列是"始终思考"型，而 `reasoning_effort` 默认是 `max`——它先想 18537 字；
2. 首字延迟几乎只跟**输入长度**有关（军师知识 6651 + 说话风格 3507 字符是绝对大头）。

显式设 `low` 后首字 8.4 秒；任务书精简后 3.0 秒；再拆成两段（第一段 3349 字符）**1.36 秒**。
"马上要用的那一句"和"完整分析"本来就可以分两次要，没理由让人为后者等前者。

**代价**：
- 多一次请求（多花一点 token），且第一段没有军师知识参与——它凭常识与说话风格出稿，
  所以第一段只给"首选"，判断与退路留给第二段；
- 服务端若哪天把 `low` 改成别的语义，或者某家不认这个参数，需要跟着调整
  （已经写了"认不出就自动去掉重试一次"的兜底）；
- 界面上多了"正在补…"这个中间态，以及一条思考流的显示。

## ADR-0023 关系背景由本人填、会话开关由本人管（0.4.0）

**结论**：

1. **人物背景由本人在界面「资料」页填**（关系 / 我叫他 / 他叫我 / 认识多久 / 雷区 /
   最近发生的事 / 其他备注），写进**同一份** `关系档案\画像\contacts\<名字>.md` 里
   一个带注释标记的区块。上游技能写的那部分**一个字不动**。
2. **每个会话一个「军师参与」开关与标签**，存 `关系档案\配置\sessions.json`（按 username）。
   判定顺序：**显式开关 > 群聊默认不给 > 标成「工作」默认不给 > 其余都给**。

**理由**：0.4.0 之前，画像里那些"关系与称呼"全是技能从聊天记录里推测出来的；本人真正知道的
（"这是我妈""他前女友不能提"）**没有地方写**。而"这个人要不要让军师插手"也不该由程序按名字猜：
群聊能自动识别（`@chatroom`），甲方和工作只能人来标。

**代价**：
- 多了一个要维护的数据文件与一处界面；
- 填错了军师就按错的来——所以这些字段做成界面上可见可改，而不是藏在文件里；
- 群聊的默认值仍然是"不给"，想开需要手动勾（这是有意的摩擦）。

## ADR-0024 全自动的触发点改为"收到新消息即接"（修订 ADR-0003）

**结论**：**修订 ADR-0003**。全自动档不再要求"本人先开聊"：授权生效期间，被授权的对象
发来新消息，程序就自动接。同时三条护栏**写死在代码里、不提供关闭开关**：

1. **静默超时自动收回**：授权挂着但一直没触发，到点（默认 30 分钟）自动撤回授权；
2. **每条都留痕**：自动发出的每一条都写进复盘文件，并在托盘弹一次提醒（事后能查它替你说了什么）；
3. **硬红线降级**：要发的这句话命中钱/承诺/见面这类词，就当场降级成草稿，**不发**。

连同原有的：群聊永不进全自动（ADR-0004）、进键盘前必须再过一次制动（ADR-0013）、
开启需要"勾选 + 输确认词"、**默认演练**（dry_run 默认为真）。

**理由**：ADR-0003 的原意是"程序不许在本人不知情时替他说话"。本人明确要求改成"收到就回"——
因为那才是这个功能真正有用的场景（不可能每次都恰好坐在电脑前等对方回消息）。
这条决定由本人拍板，记在这里是为了以后能查"为什么当年那条被推翻了"。

**代价（写在明处）**：
- 授权生效期间，**本人在不在场都会自动回复**。这正是 ADR-0003 当初拒绝的事，
  现在由本人明确要求并承担；
- 因此护栏一律不给"关掉"的开关——它们不是贴心功能，是这条决定的补偿条件；
- 默认仍然是建议档，开全自动要勾选 + 输入确认词，并且**默认是演练**（不真发）。

## ADR-0025 仓库转为公开发布：私有数据与提交史一并清理（1.0.0）

**结论**：仓库从"私有留痕 + 禁止推送"（ADR-0016）改为**公开托管**。为此做了三件事：

1. **私有数据不入库**：`关系档案\`（真实语料、联系人画像、复盘留痕、`secrets.json`）
   整目录进 `.gitignore`；程序首次运行由 `config.ensure_dirs()` 自建空目录，
   别人 clone 下来从空档案开始；
2. **提交史重建**：旧的 14 个提交与 tag（0.1.0 → 1.0.0）连同语料一起归档到 `_backup\`，
   不再随仓库发布；公开发布的历史从本次提交（tag `v1.0.0`）重新起算；
3. **示例内容中性化**：演示数据与文档里的真实人名、真实手机号、本机用户名
   一律换成中性占位（`联系人A`、`群聊A`、`123456789`、`<你的用户目录>`）。

**理由**：语料一旦推到公开托管就收不回来（会被抓取、可能被 fork）。与其靠钩子防守，
不如让仓库里根本没有这些数据——**删除是唯一可靠的脱敏**。

**代价（写在明处）**：
- 本机之外的版本史只剩 1 个提交；要回看 0.x 的逐步演进得查 `_backup\` 里的旧仓库归档；
- 真实语料与画像继续只存在本机数据根，**不随仓库迁移**——换机器要自己带走 `关系档案\`；
- 公开仓库里含"自动操控聊天窗口并发送消息"的完整实现，使用者需自行承担与各 IM 平台
  用户协议相关的风险。
